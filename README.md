An embedded vehicular telematics gateway and Powertrain Engine Control Unit (ECU) simulator built on an ESP32 microcontroller using **FreeRTOS** dual-core task scheduling, digital signal filtering, and real-time on-board diagnostic (OBD-II) state machines.

---

## 📌 Executive Summary & Architectural Motivation

In modern automotive embedded systems (such as Connected Cars and V2X nodes), microcontrollers cannot afford CPU blocking while serving high-latency wireless diagnostic requests. A missed throttle or brake sensor read due to networking overhead can violate strict safety-critical deadlines.

This project addresses this constraint by decoupling **safety-critical sensor acquisition** from **telematics communication** across the dual physical cores of the Xtensa LX6 microprocessor:
* **Core 1 (Safety Domain):** High-frequency (66Hz) ADC sampling of the Accelerator Pedal Sensor (APS) with digital low-pass filtering and fault-code evaluation.
* **Core 0 (Telematics Domain):** Low-priority wireless access point hosting an embedded web dashboard and asynchronous JSON streaming endpoint.

## ⚡ Hardware Pinout & Bill of Materials

| Component | ESP32 Pin | Function | Notes |
| :--- | :--- | :--- | :--- |
| **Potentiometer VCC** | **3V3** | 3.3V Power Supply | Rail reference |
| **Potentiometer Wiper (Output)** | **GPIO 34 (ADC1_CH6)** | Analog Voltage Input | **ADC1** is critical to prevent Wi-Fi SAR ADC conflicts |
| **Potentiometer Ground** | **GND** | System Ground | Common ground reference |

> **⚠️ Automotive Engineering Note on Pin Selection:**  
> The ESP32's `ADC2` channels share internal hardware with the Wi-Fi subsystem and fail to read analog voltages while the Wi-Fi module is transmitting. Therefore, this implementation strictly utilizes **ADC1 (GPIO 34)** to ensure deterministic sensor acquisition during high-bandwidth telemetry transmissions.

## 🧠 Key Technical Features

### 1. Deterministic Multi-Threading (FreeRTOS)
* Tasks are pinned to dedicated execution cores using `xTaskCreatePinnedToCore()`.
* Cooperative non-blocking context switching is achieved via `vTaskDelay(pdMS_TO_TICKS(...))` instead of traditional blocking `delay()` functions.
* Shared telemetry variables are protected using FreeRTOS spinlock critical sections (`portENTER_CRITICAL` / `portEXIT_CRITICAL`) to eliminate race conditions between cores.

### 2. Digital Signal Processing (DSP Filter)
Automotive electrical harnesses experience heavy electromagnetic interference (EMI) generated by alternators and ignition coils. To prevent noisy throttle fluctuations:
* Implemented a **10-sample Moving Average Filter (Low-Pass)** running inside the sensor task.
* Eliminates raw ADC quantization noise and smooths throttle response before feeding the dynamic engine model.

### 3. Diagnostic State Machine (OBD-II DTCs)
* Simulates vehicle safety monitoring loops.
* Identifies over-speed and redline conditions (`OVER_SPEED_WARN` at $>92\%$ throttle demand).
* Integrates simulated powertrain fault reporting (e.g., **DTC P0122** for Throttle Position Sensor circuit low input).

## 📊 Live Telematics Web Interface

The gateway hosts a standalone, responsive web application at `http://192.168.4.1` with zero external dependencies:
* **Gauges:** Live Accelerator Pedal Position (APS %), Engine Speed (RPM: $800 - 7000$), Vehicle Speed ($0 - 180\text{ km/h}$).
* **Diagnostic Banner:** Real-time OBD health status banner turning dynamic red during fault assertions.
* **Polling Latency:** High-frequency asynchronous JavaScript (`fetch('/data')`) updates every $150\text{ ms}$.

### Telematics REST API Endpoint
* **Request:** `GET /data`
* **Response Payload:**
```json
{
  "pedal": 45.2,
  "rpm": 3602,
  "speed": 81,
  "status": "SYSTEM_OK"
}
```
